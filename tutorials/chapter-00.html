开发环境配置

1.1 安装与验证 JDK 25

JDK（Java Development Kit）包含 Java 运行时环境及 javac 编译器等开发工具。本教程基于 JDK 25，请下载并安装与当前操作系统及处理器架构匹配的 JDK 安装包，而非仅包含运行时环境的 JRE。

下载 Eclipse Temurin JDK 25

常规 Windows 设备请选择 x64 架构，搭载 Apple Silicon 芯片的 macOS 设备请选择 aarch64 架构。安装完成后，重新打开终端并执行以下命令，确认 java 与 javac 的主版本号均为 25。

java -version
javac -version

若两者版本号不一致，请核查系统环境变量 PATH 与 JAVA_HOME。其中 JAVA_HOME 应指向 JDK 安装根目录（而非其下的 bin 目录），调整完成后需重启终端重新验证。

1.2 配置 IntelliJ IDEA

从 JetBrains 官网下载 IntelliJ IDEA

安装 IntelliJ IDEA 并导入模板工程后，请分别在以下菜单路径中将 Project SDK 与 Gradle JVM 指定为已安装的 JDK 25。[1]

中文
文件 → 项目结构 → 项目 → SDK → JDK 25
EN
File → Project Structure → Project → SDK → JDK 25
中文
设置 → 构建、执行、部署 → 构建工具 → Gradle → Gradle JVM → JDK 25
EN
Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JVM → JDK 25

1.3 创建 Fabric 模板工程

打开 Fabric 官方模板生成器

在模板生成器中选择 Minecraft 26.3，并依次填写模组名称（Mod Name）、Mod ID 及 Java 包名（Package Name）。本教程以 Vocabulary Spark、vocabulary-spark 与 io.github.piscescup.vocabularyspark 为例。由于 Mod ID 同时作为资源命名空间使用，建议在项目初始化阶段即确定其命名。[2]

开发语言选择 Java，并按项目需求决定是否启用客户端源码分离（Split client and common sources）与数据生成（Data Generation）。下载并解压工程压缩包后，使用 IntelliJ IDEA 打开包含 settings.gradle 与 build.gradle 的项目根目录，等待首次 Gradle 同步完成。

Gradle 同步完成后，在项目根目录的终端中依据当前操作系统执行对应命令，启动开发客户端（两条命令分别适用于不同系统，无需依次执行）：[3]

# Windows PowerShell
.\gradlew.bat runClient

# macOS / Linux
./gradlew runClient

若开发客户端正常启动，则表明基础开发环境已配置就绪。如启动失败，请查阅 Build 工具窗口或终端中的错误日志，并核查 JDK 配置及 Gradle 依赖同步状态。

2.8 项目文件编码：统一为 UTF-8

中文
设置 → 编辑器 → 文件编码 → 全局编码 / 项目编码方式 / 属性文件的默认编码方式

将 Global Encoding、Project Encoding 及 Properties 文件的默认编码统一设置为 UTF-8，并核查下方的文件及目录覆盖列表，避免个别目录沿用其他编码。[14]

项目文件

4.1 Gradle 构建与依赖配置

文件或目录用途
build.gradle核心构建脚本，用于声明 Fabric Loom 插件、Minecraft 及 Fabric 依赖，以及编译与资源处理规则。Minecraft 26.3 模板已采用 net.fabricmc.fabric-loom 插件。[20]
gradle.properties集中定义版本参数与项目属性，包含 minecraft_version、loader_version、fabric_api_version、version 与 group 等配置项。[21]
settings.gradle定义工程名称及 Gradle 插件解析仓库等项目级构建设置。
gradle/wrapper/gradle-wrapper.properties锁定当前工程所使用的 Gradle 发行版本。建议直接使用项目自带的 Wrapper，无需另行配置全局 Gradle。[22]
gradlew / gradlew.batGradle Wrapper 启动脚本：macOS / Linux 环境使用 gradlew，Windows 环境使用 gradlew.bat。
.gradle/ · build/本地构建缓存与编译输出目录，属于生成产物，不应纳入版本控制。

4.2 Fabric 源码、资源与元数据

位置用途
src/main/java/存放通用 Java 源码及实现 ModInitializer 的入口类。该目录代码将在客户端与独立服务端共同加载，切勿引入仅存在于客户端的类。
src/client/java/启用客户端源码分离后用于存放客户端专用代码，通常包含 ClientModInitializer 入口类。
src/main/resources/fabric.mod.json模组核心元数据描述文件，声明 id、name、version、environment、entrypoints、depends 与 mixins 等关键字段。[23]
assets/vocabulary-spark/位于 resources 下的客户端资源命名空间目录，用于存放语言文件、贴图与模型等资产，其目录名须与 Mod ID 一致。
data/vocabulary-spark/服务端数据包命名空间目录，用于存放配方、战利品表与标签等数据文件，可随功能开发按需创建。
*.mixins.jsonMixin 配置文件，声明 Mixin 类列表与注入参数；客户端专用配置可放置于 src/client/resources 目录。
src/main/generated/启用数据生成功能后的输出目录。如需调整数据内容，应修改生成器代码并重新执行生成任务，避免直接手改输出文件。

命名规范提示：Mod ID 允许使用连字符（例如 vocabulary-spark），而 Java 包名不得包含连字符（例如应写为 vocabularyspark）。两者分别用于资源命名空间与源码包路径。

开发实践

在工程实践中，建议将 Mod ID、模组元数据、日志记录器及通用工具方法集中封装于独立的 References 辅助类中，以便统一维护与引用。对于规模较小的项目，亦可将这些成员保留在主入口类中。

5.1 References 类示例

以下示例展示了完整的 References 工具类实现，通过私有构造器禁止实例化。实际使用时请补充所属 package 声明，并确保 MOD_ID 与 fabric.mod.json 中的 id 字段完全一致。

VocabularySparkModReferences.java
import com.google.gson.Gson;
import com.google.gson.GsonBuilder;
import net.fabricmc.loader.api.FabricLoader;
import net.fabricmc.loader.api.ModContainer;
import net.fabricmc.loader.api.metadata.ModMetadata;
import net.minecraft.resources.Identifier;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;
import org.jetbrains.annotations.Contract;
import org.jspecify.annotations.NonNull;

/**
 * Constants
 *
 * @author REN YuanTong
 * @since 1.0.0
 */
public final class VocabularySparkModReferences {

    private VocabularySparkModReferences() {
    }

    /** The mod identifier, also used as the namespace for mod resources. */
    public static final String MOD_ID = "vocabulary-spark";

    /** The Fabric loader instance providing access to registered mods. */
    public static final FabricLoader FABRIC_LOADER = FabricLoader.getInstance();

    /** The registered container for the mod identified by {@link #MOD_ID}. */
    public static final ModContainer VOCABULARY_SPARK_MOD = FABRIC_LOADER
            .getModContainer(MOD_ID)
            .orElseThrow();

    /** The metadata supplied by {@link #VOCABULARY_SPARK_MOD}. */
    public static final ModMetadata VOCABULARY_SPARK_METADATA = VOCABULARY_SPARK_MOD
            .getMetadata();

    /** The human-readable mod name obtained from the registered metadata. */
    public static final String MOD_NAME = VOCABULARY_SPARK_METADATA
            .getName();

    /** The friendly version string obtained from the registered metadata. */
    public static final String MOD_VERSION = VOCABULARY_SPARK_METADATA
            .getVersion()
            .getFriendlyString();

    /**
     * The shared Gson instance for JSON serialization and deserialization.
     * Uses pretty printing and disables HTML character escaping in JSON output.
     */
    public static final Gson GSON = new GsonBuilder()
            .setPrettyPrinting()
            .disableHtmlEscaping()
            .create();

    /** The shared Log4j logger named using {@link #MOD_NAME}. */
    public static final Logger MOD_LOGGER = LogManager.getLogger(MOD_NAME);

    /**
     * Creates a resource identifier using {@link #MOD_ID} as its namespace.
     * For example, {@code "textures/gui/dictionary.png"} produces
     * {@code "vocabulary-spark:textures/gui/dictionary.png"}.
     *
     * <p>The path is passed unchanged to
     * {@link Identifier#fromNamespaceAndPath(String, String)}. It must contain
     * only lowercase ASCII letters, digits, slashes, periods, underscores or
     * hyphens; a namespace prefix must not be included.
     *
     * @param path the non-null resource path within the mod's namespace
     * @return a new identifier with the mod namespace and the supplied path
     * @throws NullPointerException if {@code path} is null
     * @throws net.minecraft.IdentifierException if {@code path} contains an
     *         invalid resource-path character
     * @see Identifier#fromNamespaceAndPath(String, String)
     */
    @NonNull
    @Contract("_ -> new")
    public static Identifier fromPath(String path) {
        return Identifier.fromNamespaceAndPath(MOD_ID, path);
    }
}

5.2 字段与方法说明

字段或方法用途
MOD_ID模组唯一标识符及资源命名空间，建议在全项目中统一引用此常量。
FABRIC_LOADERFabricLoader 单例对象，用于查询已加载的模组容器与运行环境信息。[24]
VOCABULARY_SPARK_MOD依据 MOD_ID 检索对应的 ModContainer；若未匹配到容器，orElseThrow() 将立即抛出异常以暴露配置不一致问题。[24]
VOCABULARY_SPARK_METADATA模组元数据对象，供 MOD_NAME 与 MOD_VERSION 读取，避免在多处重复硬编码模组名称与版本号。
GSON共享 Gson 实例，已启用格式化输出（Pretty Printing）并关闭 HTML 字符转义。
MOD_LOGGER以模组名称初始化的 Log4j 日志记录器；引入时须确认导入 org.apache.logging.log4j.Logger。
fromPath(path)自动为资源路径附加当前模组命名空间；传入参数应仅包含相对路径，不得携带命名空间前缀。

创建贴图资源标识符的调用示例：

Identifier texture = VocabularySparkModReferences
        .fromPath("textures/gui/dictionary.png");
// vocabulary-spark:textures/gui/dictionary.png

5.3 类静态初始化时机

首次触发类初始化时，类中的静态元数据字段将按声明顺序依次求值；即使仅调用 fromPath()，也会先执行 ModContainer 查询。因此，该类应在 Fabric 完成模组元数据加载后的生命周期内调用，不宜在脱离 Fabric 运行环境的普通 main() 方法中直接测试。MOD_ID 属于编译期字符串常量，单独读取通常不触发类初始化。[25]

5.4 静态分析注解说明

@NonNull 来自 JSpecify（org.jspecify.annotations.NonNull），用于声明方法返回值非空；@Contract("_ -> new") 来自 JetBrains 注解库，用于表明方法在正常返回时始终创建新对象。二者仅服务于静态代码分析与 IDE 检查，不会在运行时执行空值校验。[26][27]

5.5 版本适配与日志框架说明

Minecraft 26.3 采用 net.minecraft.resources.Identifier 及其 fromNamespaceAndPath 工厂方法，旧版本中的 net.minecraft.util.Identifier 或 ResourceLocation 不再适用。此外，本示例采用 Log4j 日志器，而官方模板默认使用 SLF4J，导入 Logger 类型时请注意区分。[28]
